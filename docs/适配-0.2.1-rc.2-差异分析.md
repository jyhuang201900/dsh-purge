# dsh-purge 适配 dsh 0.2.1-rc.2 —— 差异分析与改动清单

分析日期：2026-10-22
基线：插件 `dshTarget: 0.2.0-rc.2`（本机桌面端实测 `dsh --version` = 0.2.0-rc.2）
目标：官方最新 tag `dsh-v0.2.1-rc.2`（2026-10-17，commit `687f282`）

## 0. 结论

86 条补丁里，**真正需要改锚点的只有 3 条（#77 / #68 / #26），另有 3 条在 0.2.1 上自动失效（#32 / #53 及 #26 的一条链式 pattern）**。
其余 80 条锚点在 0.2.1-rc.2 的已发布构建产物里逐字命中，不需要动。
注入机制面（cordis 4.0.1→4.0.5、`__ModuleLoader__.load`、槽位名、system-prompt 配置键、assemble 影子方法）全部保留。

## 1. 验证方法

- 上游源码：浅克隆 `dsh-v0.2.0-rc.2` 与 `dsh-v0.2.1-rc.2` 两个 tag。
- 真实产物：从 npm 拉取本机 asar 内全部 278 个 `@deepseek-ai/dsh-*` 包在两个版本的 tarball
  （0.2.0-rc.2 命中 277 个，0.2.1-rc.2 命中 274 个），对 `lib/**.js|yml` 做锚点全文匹配。
- 判定标准：某条 pattern 在 0.2.0 命中、在 0.2.1 不再命中 → 视为破损（DEAD）。
- 脚本与原始报告：`E:\完成项目\_scratch\anchor-ground.mjs`、`anchor-ground-report.json`、`recheck.mjs`。

## 2. 破损清单（必须改）

### #77 REWIND_DROP_SENT_ON_APPEND（file=conversation-client）

官方 `dsh-client-ui-conversation/lib/client.js` 的 `append(record)` 加了一个守卫：

```text
0.2.0:  if (this.inputs.has(event.seq)) return "none";
        this.revised.clear();
0.2.1:  if (this.inputs.has(event.seq)) return "none";
        if (this.revised.size > 0) this.revised.clear();
```

改法：保留旧 pattern（兼容 0.2.0），新增一条 0.2.1 形态的 pattern，replace 同样插入
`isRewindMarker(event)` 分支 + `// [dsh-purge] rewind drops sent messages in this conversation`。

### #68 SYSTEM_NODES_CONTENT_GUARD（file=agent-loop|session）

`dsh-agent-loop/lib/index.js` 的首发消息循环被重写，同时新增 runtime-context 分支：

```text
0.2.0:  if (firstAttempt) for (const message of decision.messages) this.session.append("user/message", message, { surfaceOp: "append" });
0.2.1:  let contextAdmitted = false;
        if (firstAttempt) for (const message of decision.messages) if (message.source.kind === "runtime-context") {
            if (context !== void 0 && !contextAdmitted) {
                this.session.append("user/message", context, { surfaceOp: "append" });
                contextAdmitted = true;
            }
        } else this.session.append("user/message", message, { surfaceOp: "append" });
```

另外每个 attempt 里多出：
`const sections = renderContextSections(this.loopCtx.systemPrompt.refreshContext(assembly, assembleContextFor(this, signal)));`
`const context = this.runtimeContext.project(joinContextSections(sections), sections);`

改法：为 0.2.1 形态补一条 pattern（在 `else this.session.append("user/message", message, …)` 处打同一标记），
旧 pattern 保留。#88 HUNG_PROMPT_REMOVED / #55 / #67 / #74 / #89 在 0.2.1 仍命中，不受影响。

### #26 MINIMAL_PERSONA_PURGE（file=preset-minimal|preset-sdk-minimal）

`dsh-web-app/presets/minimal.patch.yml` 在 persona 块和 persistent-shell 之间插入了
`tool-fs` 与 `compaction` 两组行，导致以 `- id: persistent-shell` 收尾的 pattern 失配：

```text
0.2.0:  …includeRuntimeContext: false\n          - id: persistent-shell
0.2.1:  …includeRuntimeContext: false\n          - id: tool-fs\n … - id: compaction\n … - id: persistent-shell
```

改法：把 pat1 / pat3 的尾部锚从 `- id: persistent-shell` 收窄到 `includeRuntimeContext: false\n`，
agent-instructions 行插在其后，两个版本都能命中。

## 3. 自动失效（可标 obsolete，不必改代码）

- **#32 WEB_SURFACE_IDENTITY_NEUTRAL / #53 WEB_SURFACE_PROHIBITION（file=web-app-lib）**
  0.2.1 的 `dsh-web-app/lib/index.js` 从 10 402 字节缩到 7 840 字节，整个
  `webSurfacePrompt()`（"You are interacting with the user through the DeepSeek Harness Web GUI at …"
  / "Do not start a replacement server …"）被官方删除；`DSH_WEB_URL` 的描述也从
  "Canonical local URL of the DeepSeek Harness Web GUI serving this session." 改成
  "Advertised URL of the DeepSeek Harness Web GUI serving this session."
  → 这两条补丁在 0.2.1 上找不到原文，会走 skipped；对破甲反而是好事（官方少了一段身份文本）。
- **#77 之外的 conversation 锚点（#56 REWIND_HIDE_CUT_ONLY）仍命中**，只有 #77 受影响。

## 4. 未受影响（已逐条验证）

- 47 条 OK 补丁全部命中，含核心注入链：#1/#2 agent-instructions、#25/#66/#40 system-prompt、
  #89/#55/#67/#74 agent-loop、#30/#31/#64/#65 hooks、#13/#14/#34/#35/#36 escalation(sandbox)、
  #9/#11/#12 user-approval、#42 settings、#85/#86 api-session-controller、#78 app-boot。
- 桌面端 shell 补丁（#45/#46/#82/#83/#84）：`apps/desktop/src/update-coordinator.ts` 的
  `this.updater.quitAndInstall(true, true)` 与 `host-process.ts:226` 的
  `this.exitPromise = new Promise<void>((resolve) => {` 两版完全一致。
- pi-ai 系列（#47/#49/#57/#90/#91）：宿主包是单个 `dsh-llm-pi-ai/lib/index.js`（114 KB），
  插件里这几条 pattern 属"打后形态/幂等链"，两版都不匹配属正常，无 DEAD 信号。
- `dsh-liangshen` 从来不是 npm 包（404），#24/#28/#71/#80 属可选/布局相关补丁，行为不变。

## 5. 机制面核对

| 项 | 0.2.0-rc.2 | 0.2.1-rc.2 | 结论 |
| --- | --- | --- | --- |
| cordis | 4.0.1 | 4.0.5（vendor 已发 stable） | 插件 peer `^4.0.1` 仍覆盖；只用 `ctx.get/inject/on` |
| `createShadowMethod`（assemble 守卫依赖） | 存在 | 存在，行号一致 | 兼容 |
| `window.__ModuleLoader__.load({id, factory})` | 存在 | 存在（`packages/client/modules`） | 兼容 |
| 槽位 `conversation.input.right` / `shell.overlay` | 存在 | 存在 | 兼容 |
| 客户端服务 `ctx.sessions` / `ctx.conversation` | 存在 | 存在 | 兼容 |
| system-prompt 配置键 `includeHarnessIdentity` / `personaPrefix` / `personaSuffix` | 存在 | 存在 | 兼容 |
| `PromptAssembly { sections[{name,text,interpolate}] }` | 一致 | 一致 | 兼容 |
| 0.2.1 兼容性判定 | 读 peer | **先读 `engines.dsh`，无则回退 peer** | 插件没有 `engines.dsh` → 走 peer，不会被拒 |
| 0.2.1 移除的包 | — | `dsh-invariants`、`dsh-subagent-in-process-driver` 无引用；`dsh-experimental-schedule-bundle` 仅剩 app-boot/profile 引用 | 插件均未引用，无影响 |

## 6. 需要改的元数据

- `package.json`：`dshTarget` → `0.2.1-rc.2`（纯元数据，宿主不读）；
  建议同时加 `engines.dsh: ">=0.2.0-rc.2 <0.3"` 之前先确认——一旦声明 `engines.dsh`，
  0.2.1 起 peer 规则就不再生效，范围必须自己写全。
- README 徽章/适配段落补 0.2.1-rc.2 实测结论。

## 7. 尚未覆盖的验证

本机只装了 0.2.0-rc.2，桌面 EXE 的 0.2.1-rc.2 安装包不在本机，因此：
`app.asar` 内 0.2.1 的构建产物、desktop-shell 的**打包后**文本、以及"应用"按钮的端到端流程，
都还没跑过。上面的结论建立在 npm 已发布产物 + 上游源码双重比对上，装上 0.2.1 后需要
再点一次「清洗 → 应用」复核状态面板（预期：#32/#53 显示 skipped，其余全绿）。
