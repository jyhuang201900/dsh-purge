# 无线电实验纪律：法规边界、只收优先、屏蔽环境

> 被 `radio-sdr` 引用。射频和别的领域最大的不同是：
> **发射行为会物理上离开你的设备，进入公共空间，无法撤回。**
> 一条错误的重放可能干扰航空、铁路、急救通信。

## 一、法规边界（先搞清"能不能发"）

无线电管理的基本原则：**频谱是国家资源，发射需要许可**。中国境内主要依据
《无线电管理条例》与工信部相关频率划分规定；其他国家各有对应法规（美国 FCC Part 15/97、
欧盟 ETSI）。以下是不需要"发射许可"的常见情形：

| 情形 | 是否需要许可 | 说明 |
| --- | --- | --- |
| 仅接收（RX only） | 通常不需要 | 但**部分频段禁止接收**（见下表） |
| ISM 频段低功率发射 | 免许可，但有限制 | 433.92MHz、868MHz(EU)、915MHz(US)、2.4GHz、5.8GHz；功率与占空比受限 |
| 业余无线电频段 | 需要操作证书 | 中国 CRAC 操作证；不能用于商业/实验以外的通信 |
| 航空/海事/应急频段 | **禁止发射** | 任何情况下 |
| 手机频段（GSM/LTE/NR） | **禁止** | 需要运营商许可，且干扰刑事风险 |
| 雷达/卫星上行 | **禁止** | — |

**绝对禁止接收/解码的频段**（很多国家立法禁止）：

```text
- 蜂窝网络的控制信道与语音（即使是"监听"也违法）
- 加密的政府/军事通信（接收明文部分也常有争议）
- 卫星付费电视的解密流
- 任何"未向你公开"的私人通信（窃听罪）
```

**实验前必须确认的三件事**：

```text
□ 我打算接收/发射的频率属于哪一类（ISM / 业余 / 专用 / 禁止）
□ 我的硬件功率是否超出该频段的免许可上限（HackRF 最大约 +15dBm，外接功放会超标）
□ 实验地点：是否在屏蔽环境；室外测试是否有场地许可
```

## 二、只收优先：能收就不发

接收没有法律风险（除上表禁止项），且能拿到 90% 的结论：

```bash
# 1) 频谱概览（找信号在哪）
gqrx                      # GUI，设中心频率 + 带宽，看瀑布图
# 或命令行
rtl_power -f 430M:435M:10k -i 1 -e 60 scan.csv
#   -f start:stop:step  -i 间隔秒  -e 总时长
python3 -c "
import pandas as pd, matplotlib.pyplot as plt
d=pd.read_csv('scan.csv',header=None)
plt.plot(d[2]/1e6, d[6]); plt.xlabel('MHz'); plt.show()"

# 2) 识别调制（AM/FM/FSK/OOK）
#    - 听感：FM 语音 = 调频；数据 = 咔哒声
#    - 看波形：URH / Inspectrum 打开 IQ 文件
# 3) 录 IQ（保存原始样本，供离线分析）
rtl_sdr -f 433920000 -s 2048000 -n 2048000 capture.iq
#   -f 中心频率  -s 采样率  -n 采样点数
```

**433MHz 传感器（最常见的合法实验对象）**：

```bash
# rtl_433 自动识别上百种设备协议（纯接收）
rtl_433 -f 433.92M -s 250k -F json

# 保存所有解出的报文
rtl_433 -f 433.92M -F json -M time:iso -o sensors.jsonl

# 只关注特定协议
rtl_433 -f 433.92M -R 120 -F json      # -R 指定协议号
rtl_433 -h | head -40      # 协议号在不同版本会变，以本机 -h 与官方文档为准
```

**判据**：能稳定解出 `model`、`id`、`code`、`temperature` 等字段 = 协议识别成功。
这时**不要立刻重放**，先记录：这是哪个厂商、什么设备、有没有滚动码。

## 三、实验环境搭建

### 3.1 Faraday 屏蔽（防止信号外泄）

| 方案 | 屏蔽效果 | 成本 | 适用 |
| --- | --- | --- | --- |
| 屏蔽箱（金属箱 + 导电衬垫） | −60 ~ −90 dB | 中 | 重放实验首选 |
| 屏蔽袋（防静电金属袋） | −40 ~ −60 dB | 低 | 小设备、短时 |
| 屏蔽室（专业） | −100 dB | 高 | 合规实验室 |
| 地下室 + 金属网 | 不可靠 | 低 | 不建议 |

```bash
# 验证屏蔽效果（重要：不能假设）
# 方法：箱内放发射源，箱外用手持频谱仪/另一台 SDR 扫同频段
# 期望：外部的信号强度接近噪声底
# 如果没有频谱仪，用 RTL-SDR 在箱外 1 米处扫，看是否有信号峰
```

**中国境内实验的现实约束**：多数团队没有专业屏蔽室。折中方案：
- 用**极低功率**（HackRF 的 TX 增益设到最低，`-a 0`）在**自有场地**做
- 把设备放进金属文件柜，缝隙用铜箔胶带封
- 实验前用 SDR 确认外部无同频信号（避免"你以为在箱内，其实漏了"）

### 3.2 实验室最小配置

```text
硬件：RTL-SDR（只收，约 200 元）+ HackRF One（收发，用于箱内重放）
软件：gqrx（看频谱）、URH（Universal Radio Hacker，解协议）、
      Inspectrum（看波形）、GNU Radio Companion（搭流程）
天线：433MHz 弹簧天线、2.4GHz 全向、定向八木（室外远距离接收）
衰减器：30dB SMA 衰减器（箱内测试必须，防止前端过载）
```

## 四、常见工具与"只收不发"的用法

### 4.1 URH（Universal Radio Hacker）

```bash
# 加载录制的 IQ 或 wav
urh capture.iq
# 步骤：
#   1) Interpretation: 选 modulation（ASK/OOK/FSK/GFSK/PSK）
#   2) 调参数直到看到清晰的方波
#   3) Analyze → 自动解出 bit 序列
#   4) 找 preamble / sync word / payload 的分界
# 导出为 .proto 或 .txt，供后续分析（不发射）
```

**关键判据**：解出的 bit 序列稳定无抖动（同一设备重复发送时 payload 前缀一致）=
协议解对了。抖动的多半是采样率不对或调制选错。

### 4.2 GNU Radio 只收流程

```text
osmocom Source (RTL-SDR) → 低通滤波 → FM/AM Demod → 音频 Sink 或 File Sink
                              ↓
                        ［不要接 osmocom Sink］
```

```bash
# 用 grc 打开示例
grc
# File → Open → 搜 "rtl" 或 "fm"
# 只接接收链路，绝不加 "osmocom Sink"（那是发射模块）
```

### 4.3 gqrx 的录制

```bash
gqrx
# 设 center freq、bandwidth、demod
# 点 "Record" → 保存为 .raw（IQ）
# 之后用 URH 或 Inspectrum 离线分析
```

## 五、重放的完整前置条件（不是"能发就能重放"）

重放要成立，必须同时满足：

| 条件 | 检查方法 |
| --- | --- |
| 信号未加密 | URH 解出的 payload 肉眼可读（有规律的递增字段） |
| 无滚动码/挑战响应 | 连续抓 5 次，比较 payload：完全一致 = 固定码 |
| 无时间戳/nonce | payload 里没有随发送时间变化的字段 |
| 目标接收机在范围内 | 合法实验里：屏蔽箱内的接收设备 |
| 有合法授权 | **书面**允许在屏蔽环境重放 |

```bash
# HackRF 重放（仅在屏蔽环境，且授权明确）
# 1) 先用只收录下 IQ
hackrf_transfer -r capture.iq -f 433920000 -s 2000000 -n 400000

# 2) 箱内重放（-a 0 = 最低增益，-x 0 = 最低功率）
hackrf_transfer -t capture.iq -f 433920000 -s 2000000 -a 0 -x 0

# 3) 判据：箱内的接收设备真的动作了（灯亮/继电器响），且箱外 SDR 无信号
```

**重要**：`hackrf_transfer -t` 是**发射**。在任何非屏蔽、非授权环境执行这一条
都是违规。报告里如果要写"可重放"，只能写"在屏蔽环境下验证成功"，
不能写"在真实环境验证"。

## 六、检测视角（防守方：怎么发现被监听/被重放）

| 场景 | 检测 |
| --- | --- |
| 固定码设备被重放 | 设备侧无日志，但**同一 code 在异常时间/异常次数出现**（需要接收端日志） |
| 滚动码设备 | 重放失败，且设备记录 "counter mismatch" |
| 无线入侵检测（WIDS） | 监测异常发射：同频段出现非注册设备的信号特征 |
| 频谱监测 | 固定频段的噪声底突然抬升（有人在发射） |
| 物理 | 现场出现陌生天线/设备 |

## 七、验伤信号

| 声称 | 硬证据 | 假成功反例 |
| --- | --- | --- |
| 识别出协议 | URH 解出稳定 bit 流，且字段能对应设备行为（如温度值合理） | 解出一堆随机 bit，靠"看起来像"下结论 |
| 信号是固定码 | 连续 5 次抓包 payload 完全相同 | 只抓了 1 次就断言"固定码" |
| 重放成功 | 屏蔽箱内接收设备产生预期动作（可观测：LED/继电器/串口日志） | HackRF 显示 "sent" 但设备无反应（频率偏了/调制不对） |
| 屏蔽有效 | 箱外 SDR 在同频段测不到信号峰 | 只是"没听到"，但没做基线对比 |

## 八、常见坑

1. **频率偏移**。RTL-SDR 有几十 ppm 的频偏，433MHz 上可能偏几 kHz，导致解不出。
   用 `rtl_test -p` 测频偏，或在 gqrx 里手动微调。
2. **采样率不匹配**。录 2.048MS/s，重放也必须是 2.048MS/s，否则时长和码率全变。
3. **HackRF 的 TX 增益不是线性，`-x 0` 也不是"零输出"**。它只是最小增益档，
   天线口仍有可测的射频功率。判断"是否真的没发出去"要靠箱外 SDR 实测，不要靠参数。
4. **以为"屏蔽袋"就够了**。普通防静电袋对 433MHz 衰减有限，必须用金属屏蔽袋。
5. **忽略占空比限制**。ISM 频段有 duty cycle 要求（如 EU 868MHz 的 1%），
   连续发射可能违规，即使功率合规。
6. **在天线近场测量**。近场（< λ/2π）测到的功率不代表远场辐射，会低估泄露。
7. **把"收到信号"当"能控制"**。接收只证明信号存在，不证明协议可伪造。
