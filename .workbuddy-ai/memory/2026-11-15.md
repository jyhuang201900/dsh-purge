### 图谱：graphify 抽取只到第 3 层路径
实测：技能 md **119/119 全在图里**，references **0/115 一篇都没有**。
原因：references 在 `skills/redteam/references/x.md`（第 4 层），graphify 只抽到第 3 层。
→ 后果不是"少几个节点"，是**技能与 93.7 万字深水区的逻辑联系在图谱上不存在**。
→ 修：`graphify-sync.mjs` 加 `injectReferenceEdges()`，merge 之后补第 4 层（+115 节点/+122 边）。
→ **两种布局都要认**：扁平 `references/x.md` 与独立 `references/<skill>/x.md`。
  正则不含斜杠时 `references/http-smuggling/payload-library.md` 建不出边（实测 2 处）。
→ 判据：`references 节点数 == 磁盘文件数`（115==115）。

### 社区命名：重聚类会冲掉一切
`graphify:refresh` → 重聚类 → 社区 id 变 + 117 个名字被 hub 文件名覆盖。
再跑 `graphify:label` → **又重聚类**（实测兜底名 7→4→7，id 全换）。
→ **唯一可靠做法**：`scripts/name-communities.mjs` 按社区成员的目录+标签特征起名，
  **只改名不动聚类**；然后 `graph.json` / `.graphify_labels.json` / `graph.html` **三处一起改**。
→ 踩过：只改 graph.json 时闸门报「graph.html 缺抽样社区名」（html 生成时就把名字定死了）。
→ 还踩过：`inferName` 返回空串 → labels 写成 `""` → 54 个节点 community_name 变空。
  **空串与 null 一样都是没名字，必须一起兜。**

### 代码审阅：stage_code 漏写库（真 bug）
`score_hit` 表有 `stage_code` 列、`addScoreHit` 也收到参数，但 **INSERT 语句漏了这列** → 永远 null。
→ `scoreStageOf()` 第一优先级读它 → 退化成"按 target 猜阶段" →
  **"给 5 个阶段各塞一条分"只有 internet 变 done，其余 4 个仍 pending。**
→ 这类 bug 极隐蔽：**不报错、不缺字段名，只是归属悄悄全错**。
→ 判据：**凡"表有列 + 代码收参数"，必须验到"落库值对不对"**，只看字段名存在不够。
