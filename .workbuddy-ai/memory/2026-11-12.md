1. **01:37-01:45 office-skills 缺失**
   `resources/runtime/office-skills/` 被清空，`dsh-skill-office` 启动期 `readFileSync` ENOENT → `DesktopHostFatalError`。
   修复：从插件包自带 `assets/`（7 个 skill，8 文件）复制回 `resources/runtime/office-skills/`。

2. **12:55 invalid IPC event**

   根因：`resources/app` 是**旧版宿主**的解包目录（asar 里 main.js 是 838,520 B，含 starting 分支）。`shouldExtractAsar` 只看「目录里有没有 @deepseek-ai」判 usable，stamp 缺失时 `writeUnpackedAsarStamp` 直接把当前 asar 指纹记到旧目录头上 → 永久错配。

## 关键调研结论（决定路线）

- **提示词清洗本来就是插件层做的**：`lib/identity.js` 的 `rewritePromptAssembly` 直接 `continue` 掉 `harness:identity` 段、`stripHarnessPersona()` 剥人格、按需删 mnemon/workspace-baseline。通过 `installAssembleGuard` 劫持 `prompt.assemble` 的 getter 实现，不改宿主文件。
  → 「只用插件层」在提示词上**零损失**。
- **权限无需补丁**：宿主 `dsh-base/cordis.patch.yml` 第 246/262 行就是 `DSH_PERMISSION_MODE ?? 'workspace-write'`，profile patch 覆盖 `sandbox-policy.mode` + `approval.policy` 即可。
- **长任务参数也能配置覆盖**：`bash-sandbox/pwsh-sandbox.timeoutMs`（默认 60000）、`tool-result-pruner.thresholdChars`（8192）、`tool-fs.readMaxLineLength/readMaxBytes`（2000/50KB）。
- 真正只能用代码补丁的只剩：fs-sandbox 围栏、escalation 逻辑、tool-ask failopen —— 且 danger-full-access 下多数不触发。

## 本轮改动

**宿主配置（`~/.dsh/profiles/desktop/cordis.patch.yml`，15 条目）**
```yaml
- id: sandbox-policy   config: { mode: danger-full-access }
- id: approval         config: { policy: never }
- id: bash-sandbox     config: { timeoutMs: 160000 }
- id: pwsh-sandbox     config: { timeoutMs: 160000 }
- id: tool-result-pruner config: { thresholdChars: 100000000 }
- id: tool-fs          config: { readMaxLineLength: 10000, readMaxBytes: 262144 }
- id: dsh-purge        config: { autoApplyOnStart: false }
```

**代码**
- `lib/extract-asar.js`：新增 `asarEntrySize()` / `unpackedEntryDrift()` / `readUnpackedSourceMark()` / `writeUnpackedSourceMark()`。解包目录内写 `.dsh-purge-source.json`（归档 size+mtime），补丁改 main.js 不影响它 → 只有宿主升级才触发重解。
- `lib/core.js`：`openSealedDesktopHost` 加版本闸（标记不符强制重解）+ 解包后自检（入口字节数不符回滚）+ 禁止无标记认领 stamp。
- `lib/profile-guard.js`（新）：宿主把 patch 重置成 `[]` 时，从最近**干净**备份恢复；备份若引用 node_modules 里不存在的第三方包则不恢复（脏备份写回去会被再重置一次）。
- `lib/index.js`：apply 开头调用 `guardProfilePatch()`。

## 教训

- 宿主升级会换 asar，但 `resources/app` 旧目录仍「usable」；**判断目录是否过期不能看文件大小**（补丁本来就会改），要看目录内自带的归档指纹。
- profile patch 里引用已卸载插件 = 宿主静默重置全部配置，且没有任何报错提示。
- `autoApplyOnStart` 默认 true 会在启动期禁用 asar 并重建 app 目录，一旦解包产物版本不对就锁死启动失败。现已关闭。
